# Железо Nokia 3210 4G (UMS9117 / Unisoc T107)

Источники: исходники [fpdoom](https://github.com/ilyakurdyukov/fpdoom) и [spreadtrum_flash](https://github.com/ilyakurdyukov/spreadtrum_flash)
(Илья Курдюков, public domain; копии в `work/src/`), справочные профили T107, плюс наша сверка с прошивкой 3210 11.00 HK
(`tools/t117fw.py`). Помечено, что **подтверждено на нашей прошивке** ✔, а что взято только из чужого кода (ⓘ).

## Чип

| | |
|---|---|
| SoC | Unisoc T107, внутреннее имя **UMS9117** («T117»); 22 нм |
| CPU | 1 × ARM **Cortex-A7** (ARMv7-A, Thumb-2, аппаратное деление), до 1 ГГц; ⓘ PLL от кварца 26 МГц, ступени 936 / 1248 / 1600 МГц |
| ОЗУ | ⓘ LPDDR2 с адреса `0x80000000`; fpdoom определяет размер (16/32/48/64 МБ); у 3210 — 64 МБ |
| Внутренняя SRAM | с адреса `0x0`; ✔ ядро при старте копирует сюда 0x1770 + 0xcc байт (векторы и быстрый код) |
| BootROM | ⓘ `0xffff0000`; принимает FDL1 по USB и грузит его в SRAM по `0x6200` |
| Флеш | 128 МБ NAND (у Unisoc есть таблица конфигураций NAND; чтения NAND в fpdoom пока нет) |
| Экран | ✔(fpdoom) 240×320, контроллер **ST7789P3**, подключение по **SPI** (на нашей прошивке ✔ выводы SPI0 не задействованы → экран на SPI1) |
| Подсветка | ⓘ токовые ключи в PMIC; для 3210 fpdoom использует `--bl_extra rgbw=0x14` |
| GPU | нет (графика — программно; есть LCDC с наложением слоёв и форматами пикселей) |

## Карта адресов

### Регистры (ⓘ из fpdoom, для UMS9117)

| Адрес | Блок |
|---|---|
| `0x20800000` | LCDC — контроллер вывода (слой изображения, размер, старт обновления) |
| `0x20a00000` | LCM — параллельный интерфейс экрана (у 3210 не используется, экран на SPI) |
| `0x20e00000` | AHB control (включение блоков: LCDC `0x800`, LCM `0x1000`) |
| `0x40230000` | системный таймер; `0x4023000c` — миллисекунды |
| `0x40250000` | клавиатурная матрица (KPD: ctrl, debounce, key_status…) |
| `0x40280000` | GPIO (128 линий, по 16 на банк, шаг `0x80`) |
| `0x402a0000` | PIN — мультиплексирование выводов |
| `0x402b0000` | PMU — питание доменов |
| `0x402d0000`, `0x403f0000` | тактирование, PLL («ANLG_WRAP») |
| `0x402e0000` | APB control; `0x402e00fc` — ID чипа |
| `0x40600000` | ADI — шина к аналоговому чипу/PMIC; регистры PMIC видны как `0x40608000+`: сторожевой таймер `+0x40`, подсветка `+0x180…+0x1d8`, кнопка питания (EIC) `+0x280` |
| `0x70100000` | UART1 (115200, от 26 МГц) |
| `0x70a00000`, `0x70b00000` | SPI0, SPI1 (экран) |

### Память ядра (✔ из таблицы распаковки в EXEC_KERNEL_IMAGE)

Ядро — образ, связанный компоновщиком ARM для адреса **`0x80a06000`** (совпадает с нашим `findbase.py`).
При старте функция scatter-load по таблице `{src, dst, len, fn}` раскладывает секции:

| Куда | Размер | Как | Что это, вероятно |
|---|---|---|---|
| `0x00000000` | 0x1770 + 0xcc | копия | векторы и код во внутренней SRAM |
| `0x81750000` | **512 КБ** | **распаковка lzdec2** (в файле 200 КБ) | RW-данные/код, которых не видно в образе как есть |
| `0x80000000` | 128 КБ | обнуление | системная область начала ОЗУ |
| `0x80874000…0x808ba000` | ~280 КБ | обнуление | буферы |
| `0x81650000` | 1 МБ | обнуление | |
| `0x817cfe2c` | **7.3 МБ** | обнуление | основной BSS (кучи, задачи RTOS, буферы) |
| `0x83fe0000` | 128 КБ | обнуление | верх 64 МБ |

Распаковщики `lzdec2` / `lzdec3` — простые LZ-схемы Unisoc (код в `tools/t117fw.py`).
В ядре нашлись ещё две маленькие таблицы с другими «базами» — похоже, это встроенные под-загрузчики
(например, загрузчик с карты памяти); не разобраны.

Пользовательская часть (USER_IMG): **файл вместе с 0x200-байтным заголовком DHTB лежит по `0x88000000`,
код начинается с `0x88000200`** (✔ эмулятор: ядро вызывает USER по `0x88000200`; указатели на строки попадают
в 6 757 строк при базе `0x88000200` против 1 384 при `0x88000000`). Наш проект Ghidra USER импортирован с базой
`0x88000000` для файла без заголовка, поэтому **все адреса USER в документах — «адреса Ghidra»: настоящий адрес = +0x200**
(названия функций и выводы от этого не меняются). Окно `0x88000000–0x88ffffff` — это виртуальная память: ядро
(`mmu_vm.c`) подгружает страницы USER с флеша при первом обращении (таблицы второго уровня поначалу пустые).

## Клавиатура (✔ из нашего ядра)

Матрица 5×5 из таблицы 8×8 в ядре (`@0xaf6c5c` от начала образа):

```
        col0   col1   col2   col3   col4
row0    *      7      1      DIAL   4
row1    0      3      2      DOWN   5
row2    LSOFT  LEFT   —      CENTER UP
row3    #      9      6      RIGHT  RSOFT
```

- **Клавиша загрузки (позиция 0,0) — `*`** — так и пишут на 4PDA.
- Клавиши `bl_update` (позиции 0,1 и 1,0) — **`7` и `0`**. По fpdoom, загрузка с карты памяти — удерживать (0,0), (0,1), (1,0)
  при включении, то есть **`*` + `7` + `0`**; работает только с подписанным загрузчиком, если включён Secure Boot.
- Кнопка питания/сброса — отдельный вход EIC в PMIC.

## Загрузка и подпись

- Первый загрузчик (FDL1) BootROM кладёт в SRAM по `0x6200`, FDL2 — в ОЗУ по `0x80100000`.
- ⓘ fpdoom: для Nokia на UMS9117 перед FDL нужна команда `t117_exec_dist 0x314d`.
- ⓘ fpdoom: «загрузчик должен быть подписан для телефонов с включённым **Secure Boot**»; в `fphelper_t117` есть
  `fwcrypto.c` (RSA + SHA-256) — работа с подписями образов.
- Отсюда гипотеза про вторую ревизию: ошибка `UB1132` при старых FDL может означать, что BootROM требует подписанный
  FDL (включён Secure Boot), а SV:19@2025 — ещё без него. **Не проверено**; следующий шаг — разобрать заголовок DHTB и FDL.

## NV (✔)

Формат `nvitem.bin` из `.pac`: `u32` идентификатор (`0x00f95fb1`), затем записи `{u16 id, u16 size, data}` с выравниванием
данных до 4 байт, по возрастанию `id`; конец — запись с `id & size == 0xffff`.
В сборке 11.00 HK — **309 записей, файл раскладывается полностью**. На флеше NV хранится иначе — в формате `VNTS`
(заголовок, каталог с копией, контрольные суммы — описан в fphelper). IMEI — записи по 8 байт (id 5, 377, 390, 484 ⓘ).
Смысл записей — следующий шаг.

## Сервисные коды (✔ таблица из USER_IMG, 24 кода)

Извлекается `tools/t117fw.py user <EXEC_USER_IMAGE.bin> 0x88000200` (важно: база payload `0x88000200`,
не `0x88000000`). Формат таблицы — 16-байтные записи `{указатель на строку, item, group, handler}`.
Коды с одинаковым handler делают одно и то же. Раньше писали «69 кодов» — это был подсчёт строк по
образцу `*#`/`#*`, куда попадали подстроки и языковые коды `*#00XX#` (их обрабатывает отдельный
парсер ввода, а не эта таблица).

| Код | Что | Основание |
|---|---|---|
| `*#0000#` | версия (Nokia) | fphelper/форум |
| `*#7370#` | **сброс к заводским** ⚠ | fphelper/форум |
| `*#6774#`, `*#6789#` | лицензии стороннего ПО | fphelper/форум |
| `####0000#` | версия | форум |
| `####1040#` | сведения о сети | форум |
| `####2222#` | серийный номер | форум |
| `#*786837#` | версия SVN | форум |
| `#*786646468#` | счётчики NV | форум |
| `#*8378#0#`…`#*8378#9#` | инженерное меню/тесты (подпункты 0–9, у каждого свой handler) | форум |
| `*#*#372733#*#*` | EER — инженерный режим (тот же handler `0x881148bf`, что `#*8378#0#`) | handler |
| `*#445566#` | инженерный **тест мощности передатчика**: обработчик открывает окно (таблица `0x8865a838`), его обработчик шлёт `AT+SPPOWERFB=1/0`, `AT+SPPOWERBFCOM=0,0,1` | handler `0x88116155`; смысл исправлен 14.11 — строка `UlockPhoneToActiveApp` из соседней функции |
| `####1111#` | не опознан: обработчик зовёт 4 функции без строк | handler `0x88110f63`; `is_plus_in_head` — из соседней функции, снято 14.11 |
| `*#737381#`, `*#737386#`, `*#737388#`, `*#737390#` | один механизм с 4 режимами: пишут 2 / 7 / 9 / 11 в глобальную `0x81787e84 + 0x2c` и переходят в общую функцию `0x8811f200`; что за режимы — не опознано | код |

⚠ Неизвестные коды набирать не стоит: среди них есть сброс и обновление прошивки.

## fpdoom на 3210 (ⓘ)

- Проверен на Nokia 3210 4G (TA-1618). Параметры: `--spi_mode 1 --bl_extra rgbw=0x14`.
- Запуск — из ОЗУ через `spd_dump` с самодельным FDL (`t117_fdl1.bin`), **во флеш ничего не пишется**.
- Нужны `pinmap.bin` и `keymap.bin` из ядра своего телефона — `tools/t117fw.py kernel` находит обе таблицы
  (288 записей pinmap, keymap выше) и сохраняет их в `work/fphelper/k11/`.
- Порты: Doom, Heretic/Hexen, Duke 3D/Shadow Warrior/Blood, Wolfenstein 3D, эмуляторы NES, SNES, Game Boy.
