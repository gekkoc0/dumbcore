# NV (nvitem.bin): карта записей

База — 3210 11.00.17.00 HK, сверено со всеми 8 сборками. Инструменты: `tools/t117fw.py nv` (структура),
`tools/nvxref.py` и `tools/nvhints.py` (какой код читает запись), `tools/nvmenu.py` (главное меню).

## Формат и API

- Файл: `u32` идентификатор сборки NV, затем записи `{u16 id, u16 size, data}` с выравниванием данных до 4 байт,
  по возрастанию id; конец — `id & size == 0xffff`. 309 записей, файл раскладывается целиком.
- Чтение из кода — `EFS_NvitemRead(id, len, buf)` = KERNEL `0x81184010` (→ `nvitem.c`); запись — `0x81184020`;
  длина записи — `0x80a2ef6e` (`nvitem.c`/`usernv.c`). USER зовёт их через переходники `0x880d3920`, `0x880d3928`, `0x880d36f8`.
- По меняющимся записям видно, чем отличаются регионы и моды (`work/nv_diff.json`).

### Формат VNTS — NV на флеше (отличен от `nvitem.bin`)

На флеше рабочий NV лежит в блочном формате **VNTS** (парсер `scan_nv()` в
`work/src/spreadtrum_flash/fphelper_t117/main.c:623`, сигнатура `"VNTS"` = `0x53544e56`):

| Смещение | Что |
|---|---|
| +0x00 | `u32` магия `"VNTS"` |
| +0x04 | `u32` идентификатор набора NV |
| +0x08 / +0x0A | `u16` первый / последний id (диапазон записей **сплошной**) |
| +0x0E | `u16` размер блока (степень двойки, ≥ 0x100) |
| +0x10 | `u16` число записей каталога |

- Заголовок **дублирован** (две копии блока-заголовка, должны совпадать — иначе «backup header damaged»).
- Каталог — `dir_count` записей по 0x10: `u16` контрольная сумма ссылки (по 14 байтам с +2), `u16` размер,
  `u32` смещение данных. Каталог тоже **дублирован**.
- Каждая запись (по смещению): `u16` чек-сумма заголовка (по 8 байтам с +4), `u16` чек-сумма данных,
  `u16 id`, `u16 size`, 4 байта, данные с `+12`. Все чек-суммы — `nv_checksum` (сумма слов).
- При чтении через некоторые режимы флеша байты переставлены: `"VNTS"` → `"STNV"` (`spd_dump.c:699`).
- **Две копии фиксированного NV** в разделах `0x90000001` и `0x9000000f` на телефоне с ПО 16.00 совпадают
  байт в байт (`docs/differences-16.00.md`).

## Покрытие смысла

| | Записей | Байт |
|---|---|---|
| Смысл установлен точно (код с логами или содержимое) | **98 / 309** | **34%** |
| Известна подсистема (по коду, диапазону номеров, соседям) — оценка | ~285 / 309 | ~99% |

Почти все байты — калибровки радиочасти (78%), производственные параметры и звук. Интерфейсных настроек мало
по объёму (3 КБ), но именно они нужны для целей проекта.

### Коды главного меню (запись 680)

Получены из таблицы пунктов меню в USER (`s_mainmenu_item_data`, 50 записей по 24 байта:
`{код, id текста, картинка A, картинка B, обработчик, 0}`) и текстов ресурсов. Смысл картинок зависит от стиля
(проверено по размерам, 14.11): **сетка** — A = иконка 76×76 (`IMAGE_MAINMENU_ICON_1…`), B = кольцо выделения 76×76
(`0x400000df`, одно на всех); **список** — A = общий чёрный фон 240×180 (`IMAGE_MAINMENU_ICON_63`), B = иконка пункта 160×160.

| Код | Пункт | Код | Пункт | Код | Пункт |
|---|---|---|---|---|---|
| 0x01 | Журнал вызовов | 0x0c | Параметры | 0x1a | Crossy Road |
| 0x02 | Контакты | 0x0d | Файлы | 0x1b | Ninja Up |
| 0x03 | Галерея | 0x0e | Дополнительно | 0x1c | Air Strike |
| 0x04 | Интернет | 0x0f | Himalaya | 0x1d | Змея |

| 0x06 | Камера | 0x12 | Видео | 0x1f | Блэкджек |
| 0x07 | Facebook | 0x14 | Cloud | **0x20** | **Календарь** |
| 0x08 | Радио | 0x16 | SIM-меню 1 | **0x21** | **Калькулятор** |
| 0x09 | Будильник | 0x17 | SIM-меню 2 | **0x22** | **Диктофон** |

**Выделенные пункты есть в прошивке, но не стоят в штатном меню** — их можно вывести правкой одной записи NV,
не трогая подписанный код (так делает мод schoolF2 с 0x21–0x23). Сравнение сборок:
- nogame5F2 убирает 0x07, 0x0b, 0x16–0x1c, 0x1e, 0x1f (платные игры, Facebook, SIM-меню);
- schoolF2 вдобавок убирает 0x14 (Cloud), 0x08 (Радио), 0x1d (Змея), добавляет 0x21–0x23 и ставит браузер 646 = 01;
- в GB 15.00 нет 0x14 и 0x07, в RO 11.00 нет 0x14.
- в **своей 16.00** (`docs/differences-16.00.md`): **25 пунктов**, Facebook (0x07) убран; порядок: Журнал, Контакты, Галерея,
  Cloud, Сообщения, Камера, Радио, Змея, Видео, Интернет, Будильник, Музыка, Параметры, Файлы, Дополнительно, 7 игр,
  SIM-меню 1/2.

### Сверка с ELISTE770

SHA-256 из [README ELISTE770](https://github.com/ELISTE770/nokia-3210-mod/blob/5a912f4397f596b89e879d40f36c2349419d96a5/README.md) совпадает с локальным `official_3210_11.00.17.00_QB_16ICN18HK00.pac`. На NV из этой сборки подтвердили данные [внешней карты](https://github.com/ELISTE770/nokia-3210-mod/blob/5a912f4397f596b89e879d40f36c2349419d96a5/ghidra_analysis_report/NVITEM_MENU_MAP.json): заголовок записи `0x02a8` по `0x31f14`, данные по `0x31f18`, длина 408 Б, счётчики 26/26.

Подписи отдельных пунктов в карте расходятся с таблицей USER той же сборки. В частности, `0x03` — «Галерея», `0x12` — «Видео», а «Калькулятор» — `0x21`. Для выбора пунктов используем таблицу выше и сверяем коды с USER целевой сборки.

### Формат идентификаторов ресурсов (побочная находка)

`0x40000000 | модуль << 16 | (индекс + 1)` — например, `0x400700a0` = модуль 7, текст 0x9f («Сообщения»).
Этим же способом код ссылается на картинки и тексты в `mmi_res`; теперь любую ссылку из кода можно перевести в
конкретный ресурс (`work/nv_menunames.py`).

## Рабочая (runtime) MMI-NV (0xd318–0xd343)

Отдельный слой «рабочих» настроек, которые телефон **пишет сам во время работы** (в рабочую флеш-область,
НЕ в `nvitem.bin`). 43 записи, id `0xd318`–`0xd342`.

- Чтение `FUN_8858387e(id, buf)`, запись `FUN_88583972(id, buf)` (`mmi_modu_main.c`/`mmisrv_nv.c`);
  длины — таблица `s_mmi_usernv_len`.
- `0xd31f` = выбор обоев (7 стилей × 8 байт), читает/пишет `MMISET_Set/GetWallpaperNVByStyleEx`
  (`0x882a980c`/`0x882a9884`) — см. `docs/internals/wallpaper.md`.

Что здесь хранится (по ~700 функциям-читателям, имена из логов):

- режим полёта (`MMIAPISET_SetFlyMode`), статус T9 (`SetDictionaryStatus`), видимость Bluetooth
  (`MMIBTNV_GetVisibleType`), USB-logon (`MMIAPIENG_IsUSBLOGON`);
- DAC (активация устройства): сброс к заводским, счётчик перезагрузок, смен SIM, номер фазы (`MMIDAC_*`);
- SMS Cell Broadcast + аварийные оповещения WEA (`MMISMSCB_*`), счётчики трафика (`MMI_DataCounter_*`);
- предупреждение о безопасной громкости (`SafeVolumeWarningSuppressed`), энергосбережение
  (`SetPowerSavingPreSettings`), переключатель GPRS (`GetGPRSSwitchStatus`), звуковое уведомление;
- пароль безопасности (`ReadSecurityPwd`), переадресация/CLIR/dual-SIM, режим VoLTE (`SetVolteInfo`),
  опросы NPS, время от включения (`SetNVTimeFromTurnOn`);
- будильник, быстрый набор, записи, менеджер загрузок, IM.

Точное соответствие «id → настройка» для всех 43 записей не доведено: id грузятся смешанно
(movw/литерал/вычисление), доступы — через мелкие обёртки без имён. Полную карту даст сравнение рабочего NV живого телефона (docs/backup.md).

## Настройки интерфейса в рабочем NV 16.00 — формула номеров (18.11.2026, измерено)

На 16.00 MMI-настройки лежат в **рабочем NV** (VNTS, раздел 0x90000003) под обычными номерами 3200–6500, а не 0xd3xx.
Номер считается на ходу из «MMI-id» вида `модуль << 16 | пункт`:

- `true_id = 0xc80 + Σ(число пунктов модулей 0 … m−1) + пункт` (база `0x889c39e6`; сервисные модули ничего не добавляют);
- число пунктов каждого модуля — из 37 вызовов `MMI_RegModuleNv` `0x889fca18` (r0 модуль, r1 таблица размеров u16,
  r2 число); чтение `MMI_ReadNVItem` `0x889fcc3e`, запись `0x889fcd32`.
- по формуле модуль 0x11 (инженерный) начинается с 6019, на деле — с **6021** (проверено по размерам
  всех 36 записей модуля и по началу модуля 0x12 = 6057). Откуда +2 — не выяснено ⇒ любой номер сверять по размерам.
- Пример: 0x110004 (флаг Card log, BOOLEAN) = NV **6025**.
- В рабочем NV пользователя 620 записей, из них **307 — настройки интерфейса** (диапазон 3200–6500): теперь каждая
  привязывается к модулю и номеру пункта, смысл пунктов — по таблицам размеров и коду модулей (не разобран).
