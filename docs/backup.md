# Бэкап телефона по USB (macOS / Linux)

Полная копия флеша Nokia 3210 4G **только чтением**: в оперативную память телефона загружаются его же загрузчики
FDL1/FDL2 из официального `.pac`, а на флеш ничего не записывается. Проверено на macOS (Apple Silicon), в том числе
через USB-C-хаб.

> В бэкапе ваш IMEI, серийный номер (PhaseCheck), калибровки радиочасти и личные файлы из памяти телефона.
> Храните его у себя и на внешнем носителе, никуда не выкладывайте.

## 1. Подготовка

1. libusb: `brew install libusb` (macOS) или `apt install libusb-1.0-0-dev` (Linux).
2. `spd_dump` из [spreadtrum_flash](https://github.com/ilyakurdyukov/spreadtrum_flash) с небольшим патчем
   (повтор приветствия загрузчику ПЗУ — без него телефон часто не успевал ответить):
   ```sh
   git clone https://github.com/ilyakurdyukov/spreadtrum_flash
   tools/build_spd_dump.sh spreadtrum_flash
   ```
3. FDL: распакуйте любой официальный `.pac` этого телефона (`python3 -I tools/extract_all.py <папка с .pac> <куда>`)
   и возьмите папку, где лежат `fdl1.bin` и `fdl2.bin` (во всех известных версиях ПО они одинаковые).

## 2. Снять

```sh
export SPD=spreadtrum_flash/spd_dump FDL_DIR=<папка с fdl1.bin и fdl2.bin>
tools/dump_phone.sh test      # ~1 мин: проверка связи, читает NV, PhaseCheck, boot0
tools/dump_phone.sh full      # все разделы, 4–5 мин
tools/dump_phone.sh extra     # дочитать рабочий NV и скрытый диск C: целиком
tools/dump_phone.sh hidden    # разделы вне таблицы .pac (копия NV и др.)
```

Каждый запуск ждёт телефон до 10 минут (`WAIT=…` — секунды). Когда скрипт напишет «plug in»:

1. телефон выключен (надёжнее — вынуть и вставить аккумулятор);
2. **зажать `*`** и воткнуть кабель; через 2–3 секунды кнопку можно отпустить.

Результат — `backup/<дата>_<режим>/` с журналом и `SHA256SUMS`. Перед следующим запуском **выдерните кабель**
(после выключения телефон остаётся на шине, и новый запуск схватит старое подключение).

## 3. Что читается

| Номер | Раздел | Как определяется размер |
|---|---|---|
| `0x80000001…04` | boot0, boot1, kernel, user | по заголовку DHTB (`auto`) |
| `0x90000001` | NV (калибровки, IMEI) | предел 1 МБ (данные ~0xB3000) |
| `0x9000000f` | копия NV (нет в `.pac`) | 1 МБ |
| `0x90000002` | PhaseCheck (серийник, этапы производства) | 1 МБ |
| `0x90000003`, `0x9000001a` | рабочий и пользовательский NV | по заголовку `VNTS` |
| `0x90000004` | ресурсы `mmi_res` | 32 МБ |
| `0x90000005/06`, `…13`, `…18` | прошивки DSP и CM4 | по стоковым размерам |
| `0x90000019`, `…1b`, `…1d` | DeltaNV, APN, IMSToggle | 1–2 МБ |
| `0x90000007` | скрытый диск C: (FAT12) | 4 МБ в `full`, целиком (~7 МБ) в `extra` |
| `0x80000008` | память телефона D: (FAT12) | до конца раздела, читается последней |

Файлы дисков открывает `tools/fat12ls.py` (список и выгрузка), остальные — `tools/dumbcore.py inspect`.

## 4. Подробности и грабли (измерено)

- Загрузчик ПЗУ отвечает `SPRD3`, FDL1 — «Spreadtrum Boot Block version 1.1». FDL1 грузится по `0x6200`,
  FDL2 по `0x80100000` (из `UMS9117.xml` в `.pac`).
- **Номер раздела у FDL2 — «окно» больше самого раздела.** У NV окно ~110 МБ, дальше данных — `0xFF`, а на конце
  окна FDL обрывает связь (`LIBUSB_ERROR_IO`), и сеанс теряется. У остальных разделов чтение заканчивается штатно
  (ответ `0x8a`/`0x84`). Поэтому в `full` у каждого раздела свой предел, а самый большой раздел — последним.
- `read_flash … auto` берёт размер только из заголовков DHTB и `VNTS`; у фиксированного NV такого заголовка нет.
- `scan` читает по 4 КБ со всех номеров `0x80000000–0f` и `0x90000000–2f`: так нашлись разделы вне `.pac`.
- Ошибки: `ver expected` — телефон не ответил на приветствие (нужен патч из `build_spd_dump.sh`);
  `libusb_control_transfer … TIMEOUT` сразу после старта — не выдернут кабель после прошлого сеанса;
  телефон просто заряжается — режим загрузки не пойман, повторите с зажатой `*`.
- `tools/usbwatch.sh` (macOS) пишет, какие USB-устройства появляются: режим загрузки — vid 6018 / pid 19712 (`1782:4d00`).
