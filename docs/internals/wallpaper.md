# Обои, живые обои и заставка — что умеет прошивка

Разобрано по USER 11.00 HK (Ghidra + декомпилятор). Скрипты: `work/wp_*.py`. На телефоне **не проверено**.

## Итог в одном абзаце

GIF как обои прошивка поставить не даёт, и даже если бы дала — картинка из файла сохраняется как
неподвижный битмап. Но в прошивке есть **живые обои из видео** («Живые обои», тип 4): законченный модуль,
подключённый к главному циклу, который проигрывает видео на рабочем столе по кругу. А **заставка** умеет
проигрывать многокадровую GIF (встроенная «волна» — именно анимированная заставка). Значит, анимированный
рабочий стол, скорее всего, достижим **без правки прошивки**: перегнать GIF в короткое видео и поставить его
живыми обоями. Это и надо проверить на телефоне первым делом.

## Где хранится выбор обоев

- Не в `nvitem.bin` из `.pac`, а в **рабочей MMI-NV**, id `0xd31f` (её пишет сам телефон).
  Функции `MMISET_SetWallpaperNVByStyleEx` `0x882a980c` / `MMIAPISET_GetWallpaperNVByStyleEx` `0x882a9884`.
- Формат: 7 стилей рабочего стола × 8 байт `{u16 id, u16 ?, u32 тип}`.
- Типы (`Get_Change_WallpaperInfo` `0x889ca4ac`): **0** — встроенные, **3** — из файла, **4** — живые (видео).
  При пропаже файла/видео откатывается на 0.

## Встроенные обои

Окно выбора `0x882ef772` перебирает **3** варианта — это три картинки `SJPG` 240×320 из модуля ресурсов 39
(`0x40270001…3`). Статичные; формат SJPG разобран (docs/formats/sres-format.md, `tools/sjpg.py`): это JPEG 4:2:2 без маркеров, таблицы — в ядре.

## Обои из файла

- Пункт файлового менеджера «Установить как → **Обои**» (`0x19000f`, обработчик `MMIFMM_FmmSetWallpaper` `0x889ad336`).
- Картинка один раз декодируется и сохраняется готовым битмапом (`MMIAPIIDLE_SaveWallpaperBitmap` `0x889ca37e`:
  ширина × высота × 2 или 4 байта); рабочий стол рисует этот кэш (`mmi_wallpaper.c`). Поэтому GIF из файла
  в любом случае был бы неподвижным — вероятно, поэтому пункт для GIF и не показывается.

## Живые обои (видео) — главное

- Модуль `mmiset_videowallpaper.c` (12 функций, `0x8808b766…0x8808d13e`): список видео
  (`AddFileToVideoListCallBack`), миниатюры (`WP_DisplayThumbnail`), переход к следующему видео (`MMIAPISETVWP_IsExistNextVWP`).
- Обработчик `MMIAPISETVWP_HandleVideoWallPaper` `0x8808cd98` вызывается из главного цикла (`mainapp.c`):
  при получении фокуса и перерисовке рабочего стола запускает проигрыватель (`0x8808c93e`) с повтором и
  ставит блокировку сна с меткой `VIDEO WALLPAPER` — то есть видео реально играет на рабочем столе.
- Пункт файлового менеджера для видео «Установить как → **Живые обои**» (`0x190022`, текст «Живые обои»,
  обработчик `MMIFMM_FmmSetAsVideoWallpaper` `0x889ace78`). Видимость пункта по типу файла не выяснена.
- Ожидаемые ограничения: формат как у видеоплеера телефона (3GP/MP4, не больше 320×240 — по отзывам на 4PDA),
  повышенный расход батареи, пока рабочий стол на экране.

## Заставка (screensaver)

- Встроенная полноэкранная GIF «волна» (`0x400001a6`, 7 кадров) — это **анимированная заставка**: на неё ссылаются
  окно выбора заставки `0x8811a390` (4 варианта, предпросмотр через контрол анимации) и окно `SCREEN SAVER` `0x88a7ebc2`.
- В меню «Установить как» для картинок и видео есть «**Заставка**» (`0x190021`), а также «Экран при включении/выключении»
  (`0x190023`/`0x190024`) — анимации включения тоже могут быть GIF/видео.

## Что проверить на телефоне (безопасно, без прошивки)

1. Перегнать GIF в видео и положить на карту. Пример (ffmpeg, `brew install ffmpeg`), не проверен на телефоне:
   `ffmpeg -i in.gif -vf "scale=240:320:force_original_aspect_ratio=decrease,pad=240:320:(ow-iw)/2:(oh-ih)/2,fps=15" -c:v mpeg4 -q:v 4 -an out.3gp`
   Если не откроется — попробовать 320×240 или `.mp4`.
2. Файлы → видео → Опции → «Установить как» → есть ли **«Живые обои»**? Поставить и посмотреть рабочий стол.
3. Параметры → Экран/Обои — нет ли пункта живых обоев или заставки.
4. GIF → Опции → «Установить как» → есть ли **«Заставка»** / «Экран при включении».

Если «Живые обои» есть и работают — цель «анимированный рабочий стол» решается вообще без модов.
Если пункт скрыт — следующий шаг: найти условие его видимости (вероятно, флаг в NV или в коде).

## Проверено в эмуляторе на 16.00 (18.11.2026)

- **GIF в слоте встроенных обоев рисуется.** Ресурсы 16.00: встроенные обои — модуль 39, `0x40270001…3`, SJPG 240×320
  (fmt 0x20a). Замена на SGIF (fmt 0x108, обёртка `resenc.sgif_wrap`, 12 байт заголовка + GIF89a) — рабочий стол
  (тип обоев 0) показывает GIF без правки кода. Сборка: `work/mod_test/gifwp/mmi_res_gifwp.bin` (все 3 слота,
  `boxes.gif` 220 КБ, 15 кадров) и `mmi_res_gifwp1.bin` (только слот 1, 32 цвета, 135 КБ).
- **Но картинка статичная** — на всех кадрах рабочего стола первый кадр GIF (код обоев рисует картинку один раз).
- Другие GIF в ресурсах: `0x400001a6` — заставка «волна» с пузырьками (7 кадров, 240×320, 53 КБ);
  `0x400004af`/`0x400004b0` — анимация включения/выключения NOKIA (78 кадров, «AliveAnimImage» в журнале).
- Грабли эмулятора: `MMIRES=` нужен АБСОЛЮТНЫЙ путь (иначе склеивается с папкой 11.00 → «res_module_total > 0» и падение).
- **Обои рисует элемент анимации (GUIANIM), и он GIF анимирует**: `MMIAPIIDLE_CreatWallpaperCtrl` `0x884e0ab2` →
  `0x884e08be` → `CTRLANIM_SetParam` `0x880d9284` (ctrl_info, data_info, file_info, display_info 0x3c → ctrl+0x148).
  Кадры GIF декодируются синхронно. `HandleAnimGetDataCnf` относится к асинхронному режиму. Когда в эмуляторе
  гаснет подсветка, интерфейс ставит таймеры анимации на паузу. При `KEEPAWAKE` прошивка показывает кадры
  последовательно. При обнулении байта display+8 (инструкция `strb.w r6,[sp,#0x214]` по адресу `0x884e0916`)
  поведение анимации сохраняется.
- Эмулятор: элемент обоев пересоздаётся при каждом событии заряда (`CAPIND_EVERY`, по умолчанию 5 млн блоков) — для
  проверок анимации ставить `CAPIND_EVERY=200000000`; подсветка гаснет через ~3 млн блоков после рабочего стола
  (экран «HMD» = телефон заблокирован).
- Сборка для телефона: `work/mod_test/gifwp/mmi_res_gif3.bin` (из прошитого `mmi_res_dc.bin`; слоты 1–3 = boxes,
  orange_balls, sound_check; изменены ровно 3 блоба из 3138, все 83 510 строк совпадают), в эмуляторе грузится до
  рабочего стола без новых ошибок.

## РАБОТАЕТ НА ТЕЛЕФОНЕ (19.11.2026 ~00:30)

- Записан `mmi_res_gif3.bin` (3 GIF 240×320 в слотах встроенных обоев) → **на телефоне GIF-обои анимируются**
  (фото пользователя). Патч кода не нужен. Наблюдения пользователя: `sound_check` (51 кадр) местами подтормаживает;
  во время музыки подтормаживают все.
- **Область обоев на рабочем столе = 240×240 с y=40** (строка состояния 0–39 и строка софт-клавиш 280–319
  непрозрачные, чёрные — «чёлка»). GIF 240×320 рисуется прижатой к верху → видны строки 0–239, низ обрезается.
  Решение — GIF 240×240 (запись в таблице ресурсов w=h=240): `mmi_res_gif3sq.bin` (обрезка по центру, 128 цветов),
  в эмуляторе встаёт ровно в квадрат.
- **ПРИЧИНА «чёлки» найдена (19.11, эмулятор): порядок размеров у SGIF обратный.** Стандартные GIF прошивки 240×320
  (заставка `0x400001a6`, анимация включения `0x400004af`) хранят и в таблице ресурсов, и в заголовке SGIF
  `(320, 240)`. Я записал `(240, 320)` → элемент анимации счёл картинку «альбомной» (поля ctrl+0x100/0x102 = 320×240),
  сделал буфер высотой 240 и поставил его по центру экрана (выравнивание display+0x2c = 5) → строки 40–279.
  С `(320, 240)` (`work/mod_test/gifwp/mmi_res_gif3v.bin`, `resenc.sgif_wrap(gif, 320, 240)` + `w=320, h=240`)
  GIF встаёт с y=0 до строки «Меню» (0–281), как обои из файла — без правки кода. Квадратные 240×240 больше не нужны.
  Попутно: выравнивание 0 (патч `0x884e0910` `movs r0,#5`→`#0`) прижимает буфер к верху — не понадобилось.
- Отладка эмулятора добавлена: `REGDUMP=addr:reg:len` (+`REGDUMP_N`), `MEMDUMP=addr:len` (в конце прогона),
  `MEMWATCH=addr:len[:n]` + `MEMWATCH_AT=блок` (раннее подключение ломает загрузку; уже оттранслированные блоки
  Unicorn, похоже, не ловит), `UPATCH=addr=new[=old]`.
- Нагрузка: у этих GIF меняется почти весь кадр (boxes ~51 300 из 57 600 пикс., orange_balls — весь), 10 кадров/с.
  Плюс у телефона сейчас включена трассировка (NV22+0x11=1) — лишняя работа процессора.

## Мысли про GIF на обоях после эмулятора (14.11.2026)

Это рабочие заметки, не проверенные выводы. Что изменилось в понимании:

**Что теперь известно точно (из запуска):**
- Рабочий стол при открытии читает выбор обоев через `MMIAPISET_GetWallpaperNVByStyle` (стиль рабочего стола 6,
  тип 0, id 0 на «свежем» телефоне) и `MMIAPIFMM_GetMoreWallpaperNVByStyle`; то есть код обоев — один для нескольких
  «стилей» рабочего стола, а тип обоев — число (0 встроенные, 3 файл, 4 видео — docs/internals/wallpaper.md выше).
- Кадр экрана — один буфер (`0x20b0eb40` в регистрах LCDC = DDR `0x82c3ad00` >> 2, поправка 20.11; 240×320 RGB565); контроллер дисплея копирует его
  на панель по запросу `LCD_InvalidateRect`. Анимации интерфейса (спиннеры, «волна»-заставка, видеообои) обновляют
  экран тем же путём — значит, «анимированный рабочий стол» технически = периодически перерисовывать слой обоев
  и звать обновление экрана. Ограничений «одного кадра» в железе нет.
- Декодер GIF в ядре есть (`gif_decoder.c`, `gif_res_decoder.c`, `gif_reentrant_decoder.c`), и заставка-«волна» — это
  GIF, который рисует контрол анимации (`ctrlanim*.c`), с таймером кадров. То есть **проигрыватель GIF внутри интерфейса
  уже есть** — его надо не писать, а «позвать» на рабочем столе.

**Три пути, от простого к сложному:**
1. **Без правок.** «Живые обои» из видео: GIF → видео (ffmpeg) → «Установить как → Живые обои». Если пункт есть —
   цель достигнута. Проверить на телефоне (раздел выше).
2. **Только данные (без подписи).** Подменить то, что рисуется: встроенные обои — SJPG (статичные), но, возможно,
   окно рабочего стола умеет показывать «анимацию» как фон (стиль рабочего стола с анимированным фоном, тип обоев 4 —
   видео — использует контрол анимации). Варианты: (а) положить своё видео как встроенный ресурс/файл и выставить
   тип обоев 4 в рабочем NV `0xd31f` (на телефоне — через меню, в эмуляторе — записью NV); (б) если контрол анимации
   рабочего стола принимает GIF по пути файла — тип «файл» с `.gif` (сейчас код превращает файл в статичную картинку —
   надо проверить, на каком шаге и есть ли флаг «анимированный»).
3. **Патч кода (если «замок» выключен).** В обработчике рабочего стола заменить отрисовку обоев на создание контрола
   анимации с GIF (тот же, что у заставки). Это самый прямой путь, но требует непрошитого eFuse и пересборки USER.

**Что сделать в эмуляторе, когда пойдёт отрисовка:**
- поставить счётчики/журнал на функции обоев рабочего стола (`MMIAPISET_GetWallpaperNVByStyle` и соседи из
  `mmiset_wallpaper*.c`, `mmiset_videowallpaper.c`) и посмотреть, кто и как рисует фон;
- записать в рабочий NV тип обоев 4 (видео) и 3 (файл `.gif`) и посмотреть, что делает код — без телефона;
- проверить, вызывает ли рабочий стол контрол анимации (`CTRLANIM_*`) для фона хоть в каком-то стиле.
