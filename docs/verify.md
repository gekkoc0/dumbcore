# Проверка подлинности по бэкапу

Команда проверяет подписи прошивки HMD, контрольные цифры IMEI и наличие заводской записи PhaseCheck.
Проверки выполняются локально по вашему бэкапу. IMEI и серийный номер в вывод не попадают.

## Проверка по полному бэкапу

Снимите полный бэкап в режиме `full`. Он занимает около 4–5 минут и сохраняет все четыре
образа кода, которые проверяет `verify`. [Инструкция по бэкапу](backup.md)

```sh
python3 -I tools/dumbcore.py dump full
python3 -I tools/dumbcore.py verify "backup/<дата>_full"
```

Подставьте дату из имени папки, которую создал `dump full`. Команда выведет `PASS` или `FAIL`
для каждой из восьми проверок. Если какой-то пункт вернул `FAIL`, проверьте указанный файл и причину сбоя.

## Дополнительная проверка по файлу eFuse

Если у вас уже есть `efuse.bin` с этого аппарата, можно дополнительно сверить отпечаток ключа HMD.

```sh
python3 -I tools/dumbcore.py verify "backup/<дата>_full" --efuse efuse.bin
```

## Что именно проверяется

| Проверка | Что значит провал |
|---|---|
| Подпись boot0/boot1/ядра/USER одним из трёх известных ключей HMD, и подпись реально сходится с данными | код прошивки не от HMD, либо файл повреждён/урезан |
| IMEI в NV (две записи): 15 цифр, верная контрольная цифра, два номера разные | данные NV повреждены или это не заводская запись |
| Заводская запись производственных этапов (PhaseCheck) не пустая | файл отсутствует или запись пуста |
| (с `--efuse`) eFuse содержит хэш ключа HMD | отпечаток в предоставленном файле не совпал |

## Честные ограничения

- Результат относится к содержимому файлов. Состояние корпуса и совпадение с наклейкой проверяются отдельно.
- Для проверки блокировки IMEI нужна информация от оператора связи.
