# Как телефон работает «вживую» (по эмулятору)

Всё ниже — не догадки по статике, а то, что прошивка сама сделала и написала в журнал при запуске в эмуляторе. Сборка — официальная 11.00 HK. Адреса ядра — настоящие; адреса USER — **настоящие**
(в Ghidra-проекте USER они на 0x200 меньше, см. docs/internals/hardware.md).

## 1. Ход загрузки ядра

| Шаг | Что происходит | Где |
|---|---|---|
| 1 | вход `0x80a061f4` (вектор сброса `ldr pc,[pc]`): кэш, FPU, стеки режимов | ядро |
| 2 | scatter-load: код в SRAM `0x0`, распаковка `0x81750000`, обнуление BSS | docs/internals/hardware.md |
| 3 | шина ADI к PMIC, сторожевой таймер, системные таймеры (`0x4023000c` мс, `0x40040004` быстрый счётчик) | `adi_phy.c`, `timer_hal.c` |
| 4 | чтение eFuse внутри PMIC (статус `0x8314`, биты 0x04/0x10) | `pmic efuse read` |
| 5 | контроллер прерываний GIC (`0x12000000`), таблица обработчиков | `gic_phy.c` |
| 6 | **экран**: драйвер панели **ST7789P3_YH_BOE** (`ST7789P3_YH_BOE_Init`, чтение ID командами `DA/DB/DC`), 377 записей в SPI1, первая очистка экрана | `lcd_if_spi.c`, `lcd.c` |
| 7 | подсветка: яркость из NV (`prod_param.c` → `lcd_backlight.c` → `analog_hal.c`) | |
| 8 | звуковой кодек SC2720 (детектор гарнитуры) | `sprd_codec_*` |
| 9 | NV: фиксированный (id < 50000) из раздела NV; DeltaNV — профили VoLTE операторов (docs/formats/deltanv-ims.md) | `nvitem.c` |
| 10 | чтение разделов по именам: файл ресурсов, прошивка CM4, DSP GSM и LTE | BSD, `init.c` |
| 11 | модем: ID чипа `0x98180000` выбирает образ CM4; питание домена модема (PMU `0x402b00d4` = 6 «включён»); железо модема и радиочасти (`hal.c`), параметры RF | `drv_bb_*`, `drv_rf_*` |
| 12 | запуск ThreadX: дальше всё — потоки и прерывания (тик — `TB_AP_TMR0_INT`, линия 61) | `threadx_os.c` |
| 13 | вход в USER `0x88000200` — инициализация интерфейса (аудиокодеки, приложения) | |

Диагностика: UART1 (`0x70100000`) сразу начинает слать кадры `7E … 7E` диагностического протокола Spreadtrum.
Свой журнал прошивка пишет через `0x810c070e` (printf-подобный, им пользуется и USER) и `0x810c0688`;
`assert` — `0x810bdf60` (выражение, файл, строка) и `0x810bfc4a` (с сообщением). Выключение питания —
`0x80a06aec` (`chip_phy.c`: последние шаги и пустой бесконечный цикл).

## 2. Память во время работы

- **USER подкачивается по требованию** (`mmu_vm.c`): окно `0x88000000–0x88ffffff` отображено через таблицы второго
  уровня, которые поначалу пусты; при первом обращении ядро читает страницу с флеша. За запуск до рабочего стола
  нужно ≈3 000 страниц по 4 КБ (почти весь USER).
- **Кадр экрана** лежит во **внутренней памяти** чипа, `0x20b0eb40`, 240×320 RGB565. Контроллер дисплея LCDC
  (`0x20800000`) сам забирает его и выталкивает в SPI: адрес кадра `+0x24`, ширина `+0x30`, высота `+0x2c >> 16`;
  запуск передачи — `0x80b1e68c`; по окончании — прерывание `TB_LCDC_INT` (51), драйвер ждёт его до 200 мс
  (`0x80b1e2d4`, иначе `assert "lcd invalidate timeout"`).
- Кучи интерфейса: пулы `vector font cache` (128 КБ), `store font cache` (128 КБ), `advance font cache` (32 КБ) —
  кеши растеризованных глифов наших шрифтов `sfon`.

## 3. Потоки ThreadX (59 штук)

Из блоков управления потоками в памяти (сигнатура `THRD`), приоритет — меньше = важнее:

| Приоритет | Потоки |
|---|---|
| 0–2 | `hisr0/1/2` (обработчики прерываний второго уровня), `mbox_send_thread`, `System Timer Thread` |
| 4–30 | `T_P_CHNG_FREQ`, `RTOS_Manage`, `LTE_layer1_adx`, `Mux RECV TASK1/2` |
| 58–101 | `THERMAL_SRV`, калибровки GSM/TD, `T_TIMESVR`, `T_P_ODM`, **`CHGMNG_SRV`** (заряд), **`T_KPDSVR`** (клавиатура), `T_VOICE_PROCESS` |
| 179–231 | связь и сервисы: `T_P_LTE_OM`, аудио (`AUDIO_HAL_TASK`, `SPRD_CODEC_TASK`, `T_AUDIO`), `T_CM`, `T_DIAG`, CM4, `fm_sipc_thread`, Bluetooth (`T_BT_SCHED`, `T_BT_SBC`), USB, `T_P_ATC` (AT-команды), `SCM_TASK` (карта памяти), `RTP`/`STRM`, **`T_LCD`** (экран), камера/картинки (`TASK_ISP_SERVICE`, `T_IMG_PROC_*`, `T_JPEG`, `T_IMG_DEC`), **`T_P_APP`** (интерфейс), FAT, `NETMGR`, DRM, SNTP |

## 4. Драйверы и их «ручки»

| Подсистема | Что узнали |
|---|---|
| ADI → PMIC | адрес чтения в `0x40600028`, ответ в `0x4060002c`: старшие 16 бит — эхо адреса (`(адрес & 0x1ffff) >> 2`), младшие — значение; бит 31 — «занят». Регистры PMIC видны как `0x40608000+` |
| NV | фиксированный (id < 50000): `nvitem.c` `0x80a2ef90` чтение, `0x80a2f016` запись, `0x80a2ef6e` длина; `EFS_NvitemRead/Write` `0x81184010/20` разводят по номерам; **рабочий** NV интерфейса (id ≥ 50000) — отдельное хранилище, у свежего телефона пустое |
| Флеш | слой разделов BSD: `0x80e07adc` открыть по имени («BML MMI Resource Partition», «BML APN Partition», «BML delta NV Partition», «BML IMS TOGGEL Partition», «BML CM4 Code  Download Partition», «BML GSM/LTE DSP Code Partition»…), `0x80e08306` сведения (+0x8c размер сектора, +0x98 число секторов), `0x80e07bea` чтение, `0x80e07b80` закрыть. Под ним — контроллер NAND `nfc_drv.c` |
| Заряд | `charge.c`: напряжение батареи — медиана трёх отсчётов `0x80a27e50`, сглаживание `0x80a28e64`, OCV по топливомеру (`_CHGMNG_Fgu_Get_Vbat_Ocv`); ниже порога из таблицы — выключение через `0x80a06aec`; температура вне −20…60 °C — тоже |
| RTC | `rtc_phy.c`: ждёт, пока сбросятся биты «идёт обновление» (`0xf00`/`0xf000`) в кешированном статусе |
| Клавиатура | `kpd_phy.c`: прерывание — логическое 0x24 (линия 68), `+0x08` флаги (биты 0–3 нажата в слоте, 4–7 отпущена), `+0x2c` позиции (байт на слот: строка << 4 \| столбец), номер = строка + 8 × столбец → код из таблицы раскладки ядра (центр 0x0d = строка 3, столбец 2); `keypad.c` шлёт службе `T_KPDSVR` сигнал `0x201` (нажата) / `0x202` (отпущена) |
| Экран | см. раздел 2; обновление из интерфейса идёт через `guilcd.c InvalidateLcdRect` → ядро `LCD_InvalidateRect` (`0x80b4d7ec`) |
| Модем | при старте: выбор образа CM4 по ID чипа, ожидание домена питания, «почтовый ящик» к CM4 (`mbox_phy.c`), загрузка DSP, `hal.c` (`0x80ce33da`) — железо модема и RF, `0x80cc35c8` — стек связи; интерфейс переживает их отсутствие |

## 5. Запуск интерфейса (USER)

1. Регистрация аудиокодеков (`amr_arm_adp.c`, `midi_adp.c`, `apm_codec.c`), приложений, кешей шрифтов.
2. **Условие запуска** — глобальная `0x8175c608`: 1 обычное включение, 3 зарядка (выключенный телефон на зарядке).
3. Автомат «Startup» (`Startup, Current State… Current event…` → `Enter this state, call enter win`), проверка кода
   продукта (`MMIAPISET_is_ProdcutCode … 16ICN18HK00`), инициализация главного меню (`MMIMAINMENU_*`, массив id пунктов),
   камеры (сенсор **GC032A**), файловой системы (`D:\System\…`).
4. Окно рабочего стола: `IdleWin_HandleMsg MSG_OPEN_WINDOW`, чтение обоев (`MMIAPISET_GetWallpaperNVByStyle`:
   стиль рабочего стола 6, тип 0, id 0), строка состояния (SIM, батарея 100%).
5. **Первое включение:** у свежего телефона (пустой рабочий NV) после логотипа открывается мастер — автомат «Startup»:
   `StartupCtrl_Language` → проверки SIM Vodafone (пропуск) → `NeedPinPuk` → `TimeSet` («Date and time») → `Data`
   («Preferred data SIM») → `TextSizeEnter` («Text size») → гарантия («Warranty») → `PowerSaveEnter` → рабочий стол.
   Дальше — блокировка клавиатуры: «Unlock», затем «Press * to unlock»; меню открывается центральной кнопкой с выделенным центральным пунктом.
   Обои рабочего стола декодируются аппаратным JPEG-блоком (`JPEG_VspOpen`).
6. **Отрисовка:** интерфейс рисует слои в DDR (основной — 240×320 RGB565, всплывающие — ARGB8888) и отдаёт их ядру через
   `layer_blend.c` (`0x80dc6a28`); ядро перекладывает их во внутреннюю память, LCDC смешивает (режим захвата в `0x20b0eb40`) и шлёт в экран.
   Формат описателя слоя: +0x14 буфер, +0x20 ширина | высота << 16, +0x24 x | y << 16, +0x28 формат (3 = RGB565, 0 = ARGB8888), +0x30 прозрачность.
7. Камера: при старте интерфейс опрашивает датчик GC032A по I2C и ждёт ответа в потоке `T_P_APP` — без датчика интерфейс бы завис.
