# Формат ресурсов `mmi_res_240X320_*.bin` (sres0001)

Разобран по официальной прошивке 3210 11.00.17.00 HK и проверен на всех стоковых сборках 10.00, 11.00, 14.03 и 15.00:
в каждой файл раскладывается на структуры на 99.99–100%. Числа little-endian.

## Верхний уровень

| Смещение | Что |
|---|---|
| 0x000 | `sres0001` |
| 0x008 | u32 = 0x10, u32 = 0x00010400 (версия формата?) |
| 0x010 | u32 смещение `tres`, u32 размер `tres` (главное дерево ресурсов) |
| 0x018…0x11B | нули |
| 0x11C | доп. секции `{char tag[4], u32 off, u32 size}`: `logo`, `logo`, `lang`, `cscs` |
| 0x14C | начало `tres` |

Директория секций заполняется с конца заголовка (0x11C…0x14B), до неё нули.

- `logo` ×2 — экран включения и выключения: обычный BMP 240×320, RGB565 (`compression = 0x1003` = BI_BITFIELDS | флаг сжатия 0x1000),
  строки снизу вверх сжаты тем же RLE, что и кадры `VM` (см. ниже). После каждого логотипа 12 байт хвоста
  `{u16 w, u16 h, u32 1, u32 size}`. В 10.00–15.00 — надпись «NOKIA», в 14.03 CN — «HMD / Makers of Nokia phones».
  Декодер: `tools/vmbmp.py: bmp_rle565()`.
- `lang` — список языков сборки: `u32 0`, затем по 24 байта на язык `{u32 номер, char имя[20]}`.
  11.00 HK: English, SimpleChinese, Arabic, Malay, Russian, Hebrew, Bengali-BD, Chinese-hk; в RU-моде 10 языков.
- `cscs` — словарь «официальных имён» заменяемых ресурсов (533 шт. в 11.00 HK): `u32 0`, затем записи
  `{u8 тип, u8 модуль, u16 0, u32 индекс, u32 0, char имя[]}`, имя с нулём и выравниванием на 4.
  Тип — как у таблиц модуля: 0 image (477 шт., `IMAGE_MAINMENU_ICON_*`, `IMAGE_WALLPAPER_1..3`…), 5 data (`R_NETWORK_BOOKMARK`), 6 color (55 `COLOR_RES_*`).
  Именно эти ресурсы перечисляет ResOver; для своего редактора это готовая таблица имён.

## tres (смещения от начала tres)

| Смещение | Что |
|---|---|
| 0x000 | `tres0001`, u32 0x10, u32 0, u32 размер |
| 0x014 | u32 module_off[128]; 0 = модуля нет. В 3210 занято 60 слотов (в 14.03 CN — 55) |
| 0x214 | версия, `1.0.0` |
| 0x294 | имя темы, `DEFAULT` |

## Модуль (смещения от начала модуля)

Модуль соответствует приложению MMI: общие ресурсы, настройки, сообщения и т. д.
Заголовок 0x60 байт — 8 записей `{u32 table_off, u32 count, u32 size}`, по одной на тип ресурса.
Таблицы типов идут подряд: `table_off[k+1] = table_off[k] + size[k]`, и в `size` входят и индекс, и сами данные.

| k | Тип | Индекс | Данные |
|---|---|---|---|
| 0 | image | `u32 p_info, u32 p_data`; `info[n] = {u16 w, u16 h, u32 fmt, u32 size}`; `data_off[n]` | см. форматы ниже |
| 1 | anim | так же, как image | 3 × `SMOV`, 1 × `VM` — см. «Анимации» |
| 2 | ring | `{u32 fmt, u32 size, u32 off}` × n | MIDI, WAV, MP3, AMR — стандартные файлы |
| 3 | text | `{u32 p_offtable, u32 size}` × nlang, затем по языку `u32 str_off[n]` | строка: ASCII с нулём в конце, либо `80 00` + u16 длина в байтах + UTF-16LE |
| 4 | font | `{u32 id, u32 p_desc}` × n; desc = 8 × `{u32 size, u32 p_data}` (слоты размеров, обычно одинаковые) | `sfon` + тег письменности (`latn`, `han`, `hani`, `arab`, `cyrl`, `hebr`, `beng`), 1000 единиц на em |
| 5 | data | `{u32 fmt, u32 size, u32 off}` × n | только в модуле 0 (430 шт.) — см. «Блоки данных» |
| 6 | color | `{u32 rgb565, u32 flag=1}` × n | цвета интерфейса (COLOR_RES_* из ResOver) |
| 7 | rect | `{i16 x0, y0, x1, y1, u32 flag}` × n | прямоугольники разметки |

Все смещения внутри модуля (`p_info`, `p_data`, `data_off`, `str_off`, `p_desc`) считаются от начала модуля.

## Форматы картинок (поле fmt)

| fmt | Сигнатура | Сколько (11.00 HK) | Статус |
|---|---|---|---|
| 0x316 / 0x30c | `ABMP` | 994 | **разобран**, декодер из прошивки |
| 0x316 / 0x30c | `ABMR` | 903 | **разобран**, декодер из прошивки |
| 0x31a / 0x310 | `sabm` | 215 | **разобран**: обёртка над ABM или сырые 32-битные пиксели |
| 0x001 | `BM` | 499 | обычный BMP |
| 0x108 | `SGIF` + 12 байт заголовка | 6 | внутри обычный GIF89a (в том числе анимированная «волна» 240×320) |
| 0x20a | `SJPG` | 3 | **разобран**: три стоковые обои 240×320 (модуль 39), JPEG без маркеров — см. ниже |
| 0x420 | `user` | 1 | заглушка 28 байт: `user` + 8 нулей + имя слота (`IMAGE_COMMON_BG`); картинку подставляет MMI во время работы |

Экспорт всех картинок в PNG: `python3 -I tools/export_images.py <mmi_res.bin> <папка>` (там же `index.html`).

### Откуда известен формат

Декодер прочитан из прошивки (KERNEL_IMG 11.00 HK, база загрузки `0x80a06000`, модуль `alpha_res_decoder.c`):

| Адрес | Что делает |
|---|---|
| `0x80db49b0` | `img_res_decoder.c`: определяет тип ресурса (BMP / ABM / sabm / GIF / JPEG) |
| `0x80ba5d1a` | разбор заголовка ABM |
| `0x80ba694e` | выбор декодера по 4-й букве сигнатуры: P/S → таблица `0x814fd688`, Q → там же, R/T → `0x80ba6d76`, U → `0x80ba706c` |
| `0x80ba54f6` | ABMP → RGB565 |
| `0x80ba6d76` + `0x80ba4a40` | ABMR: цикл по строкам + разбор строки |
| `0x815dcb70` | таблица порогов разрядности (2, 4, 8 … 32768) |
| `0x815dcb8e` | таблица 4-битной прозрачности для S/T |

Пользовательская часть (USER_IMG) грузится по `0x88000000` и зовёт ядро через переходники `ldr pc,[pc,#-4]` в районе `0x880d2xxx`.
Инструменты: `tools/armre.py` (capstone в `work/.venv`), `tools/findbase.py`.

### sabm

`'sabm'`, байт режима (`01` — внутри ABM, `08` — внутри сырые пиксели), 3 байта флагов, u16be ширина, u16be высота, данные.
Сырые пиксели: `w×h×4` байт; порядок каналов принят B, G, R, A (ARGB8888 little-endian) — по коду ещё не подтверждён.

### ABM (ABMP, ABMR и варианты S/T/Q/U)

Все числа заголовка big-endian.

| Смещение | Что |
|---|---|
| 0 | `ABM` + вид: `P` (упакованный), `R` (RLE); `S`/`T` — то же с 4-битной прозрачностью; `Q`/`U` — палитра по 3 байта |
| 4 | u16 ширина, u16 высота |
| 8 | u16 `a` — номер первого полупрозрачного цвета; u16 `b` — сколько их |
| 12 | u8 поля: **сверху, слева, снизу, справа** — пиксели хранятся только в прямоугольнике `x0=left…w−1−right`, `y0=top…h−1−bottom` |
| 16 | палитра `N−1` цветов, `N = a+b`: RGB565 big-endian (Q/U — 3 байта) |
| … | прозрачность: `b` байт (S/T — `b` полубайт, старший первым), затем выравнивание до чётного смещения |
| … | данные |

Значение пикселя `v`: 0 — прозрачный; `1…a−1` — `palette[v−1]` непрозрачный; `a…N−1` — `palette[v−1]` с прозрачностью `alpha[v−a]`.
Разрядность: `ceil(log2 N)`, минимум 1.

- **P**: индексы подряд по строкам внутри прямоугольника, без выравнивания строк. Поток — 16-битные слова **big-endian**, биты берутся с младших.
- **R**: `u32le L`, затем `L` байт пар `(n, f)` по строкам: `n` литеральных индексов, потом (если `f≠0`) один индекс, повторённый `f` раз; пара `(0,0)` завершает строку.
  Затем поток индексов — 16-битные слова **little-endian**, биты с младших.
- Хвостовые нулевые байты потока энкодер обрезает; читать за концом нулями.

Проверка: все 1 104 ABMP и 958 ABMR из 11.00 HK декодируются без индексов вне палитры, а RLE-таблицы у всех ABMR сходятся с шириной картинки байт в байт.

## SJPG (встроенные обои)

`'SJPG'`, `u16be h`, `u16be w`, `u16be a`, `u16be b`, дальше — энтропийно закодированные данные baseline JPEG
(с byte-stuffing `FF 00`, но без маркеров SOI/DQT/DHT/SOF/SOS). Всё недостающее берётся из ядра:

- Хаффман — стандартные таблицы ITU-T T.81 Annex K (лежат в ядре сразу за таблицами квантования).
- Квантование — 5 уровней, ядро 11.00 HK по смещению файла 0xb863a4 (яркость) и 0xb864e4 (цветность), шаг 0x40,
  в естественном порядке; это Annex K, масштабированный под качество ≈40/50/70/85/95. Уровень = поле `b` (у всех трёх обоев 4).
- Субдискретизация 4:2:2 (Y 2×1, Cb/Cr 1×1); поле `a` = 3 у всех — видимо, код этой схемы.

`tools/sjpg.py` собирает из SJPG обычный JFIF (таблицы сверены с ядром байт в байт); Pillow декодирует все три без ошибок.

## Анимации

**SMOV** (декодер ядра 0x80ba681c, alpha_res_decoder.c): `'SMOV' 'ARGB'`, `u16be X` (=24 у всех; ядро кладёт в поле +8
описания картинки, смысл не подтверждён — похоже на fps/задержку), `u16be n_frames`, `u32 0`, `u32be offset[n]` от начала блоба;
каждый кадр — обычный ABMP. Тип картинки в ядре = 7. Стоковые: спиннер загрузки 30×30 (12 кадров), спиннер 24×24 и замок 24×24 (по 8). `tools/smov.py`.

**VM** — многокадровый BMP (bmp_io.c 0x80ba4878, bmp_decoder.c 0x81307cc2/0x813072a2): заголовок BMP с сигнатурой `VM`,
`bfReserved` = цвет-ключ (RGB888) прозрачности, `compression = 0x1003`, маски RGB565. По `bfOffBits`: `u32 n_frames`,
затем `{u32 size|flag, u32 offset}` × n; бит 31 = 1 — кадр без сжатия, 0 — RLE. Строки снизу вверх, RLE строки (ядро 0x81306488):
`u8 n_lit, u8 n_rep`, `n_lit` пикселей u16, потом один пиксель, повторённый `n_rep` раз; `00 00` — конец строки.
Кадр 0 рисуется целиком, остальные — поверх предыдущего с прозрачным ключом (дельта-кадры). Единственный экземпляр —
старая иконка «поиск» 23×24, 4 кадра. `tools/vmbmp.py`.

## Блоки данных (тип 5, модуль 0)

Логический файл режется на блоки ≤ 15 360 байт, идущие подряд; цепочки разделены пустыми слотами (блок длиной 1 байт `00`, их 383).

| Что | Блоки (11.00 HK) | Формат |
|---|---|---|
| `BKMK` закладки браузера | #0, 212 Б | `'BKMK'`, `u16 1`, `u16 n`, `u32 off[n]`; запись: `u16 len` + имя UTF-16LE, `u16 len` + URL ASCII, оба с нулём и выравниванием 4. 5 китайских сайтов (Baidu, Qidian, Sogou, Weibo, Sohu) |
| T9 LDB английский | #1–3 | словарь Nuance/Tegic T9: `Copyright © 2022 Tegic Comm.…`, байт 0x36 = язык (Windows LANGID) |
| T9 LDB арабский | #19–28 | язык 0x01 |
| T9 LDB бенгальский | #55–63 | язык 0x4b (в Windows это каннада, но из 8 языков сборки нелатинский без словаря — только Bengali-BD) |
| T9 LDB иврит | #124–132 | язык 0x0d |
| T9CC китайский | #367–381 | база китайского ввода T9 (пиньинь/черты), блоки с сигнатурой `34 12` и таблицы |

В RU-сборках вместо них EN, 0x61, RU 0x19, UK 0x22, 0x8f. Внутренности LDB — закрытый формат Nuance, читает его только библиотека T9;
для наших целей это непрозрачные блобы (менять/удалять можно только целиком). Пустые слоты рингтонов — 14 байт `is null temply`.

## Запись (tools/sreswrite.py, tools/imgenc.py)

**Раскладка, по которой пересобирается файл** (измерено на всех стоковых сборках):
- модули в tres идут встык, таблицы внутри модуля — встык, в порядке типов 0…7;
- в таблицах image/anim/ring/data блобы лежат в порядке индексов, без повторов, каждый с выравниванием 4 байта
  от начала модуля; заполнитель — `0xAD` (image), `0xBD` (anim), `0xCD` (ring, data); так же добита и вся таблица;
- размер tres хранится дважды: в заголовке файла (+0x14) и в заголовке tres (+0x10);
- все указатели внутри модуля — от начала модуля, поэтому неизменённую таблицу при сдвиге достаточно
  «перебазировать» (image/anim: `p_info`, `p_data`, `data_off`; ring/data: `off`; text: `p_offtable`, `str_off`;
  font: `p_desc`, `p_data`); секции после tres (`logo`, `lang`, `cscs`) сдвигаются целиком.

Проверки: без изменений — файл байт в байт; принудительная перестройка **всех** таблиц картинок/анимаций/звуков/данных —
байт в байт во всех 7 сборках; увеличение одной картинки на 37 байт — все остальные ресурсы (тексты, шрифты, звуки,
цвета, секции) читаются как прежде. RU-мод `nogame4F2` не поддерживается (ResOver нарушает раскладку) — сборщик это видит и отказывается.

**Правила стокового энкодера ABMP/ABMR** (восстановлены так, что все 10 324 картинки P/R пяти стоковых сборок,
закодированные заново *из одних пикселей*, совпадают с оригиналом байт в байт):
- палитра: непрозрачные цвета по убыванию RGB565, затем полупрозрачные по убыванию (альфа, цвет); в палитре только
  используемые цвета; индекс 0 — прозрачный;
- рамка `top/left/bottom/right` — по видимым пикселям;
- после палитры и альфы выравнивание на чётный адрес байтом `0xFF`;
- P: поток целыми 16-битными словами;
- R: строка режется на пары (литералы, повтор): повтор — от 3 одинаковых значений подряд, а последняя серия строки
  повторяется всегда (даже из одного значения); не больше 255 в паре; поток индексов — `2·(бит/16)` байт, плюс 1 байт,
  если в последнем слове 1–8 бит, иначе плюс 2 (полностью заполненное последнее слово получает ещё одно пустое).

Команда: `work/.venv/bin/python -I tools/sresedit.py <mmi_res> <новый файл> IMAGE_MAINMENU_ICON_CALCULATOR=calc.png`
(имя из секции `cscs`, или `модуль:индекс`, или id `0x40MMIIII`; `--names [фильтр]` — список имён).
PNG того же размера, что и оригинал; вид (P/R) и обёртка `sabm` сохраняются.

**Таблица шрифтов** (тип 4): `{u32 id, u32 p_desc}[n]`, затем описания — по S слотов `{u32 size, u32 p_data}` на шрифт
(S = 7, 8 или 11 в зависимости от сборки; все слоты шрифта указывают на одни и те же данные), затем файлы `sfon`,
выровненные на 4, заполнитель `0xDD`. Замена шрифта (`SresWriter.set_font`) проверена так же: перестройка байт в байт
во всех 7 сборках, увеличение шрифта меняет только его.

**Таблица текстов** (тип 3): `{u32 p_tab, u32 words}` на каждый язык, затем таблицы смещений **всех** языков подряд
(`u32 str_off[n]`), затем строки — язык за языком, в порядке номеров; одинаковые строки внутри языка хранятся один раз
(между языками не склеиваются); каждая строка добита нулями до 4 байт; `words` = байты строк этого языка с добивкой / 4.
Кодировка строки: если все символы < 0x100 — Latin-1 и нулевой байт (так хранятся и «Móvil», «Unité»), иначе
`80 00` + u16 длина в байтах + UTF-16LE без терминатора. Порядок языков — как в секции `lang`.
Перестройка всех таблиц текстов из декодированных строк — байт в байт во всех 7 сборках.

**Таблица цветов** (тип 6): `{u32 rgb565, u32 flag = 1}`, 55 штук в модуле 0, имена `COLOR_RES_*` из `cscs`.
Какие из них интерфейс реально использует, а какие цвета зашиты в код или в картинки — на телефоне не проверено.

Команды (`tools/sresedit.py`):
```bash
python3 -I tools/sresedit.py <mmi_res> --find "Сообщения" Russian     # -> text:0:2, text:0:2906, ...
python3 -I tools/sresedit.py <mmi_res> --colors
python3 -I tools/sresedit.py <mmi_res> <новый> "text:0:2@Russian=СМС и чаты" COLOR_RES_IDLE_TIME=#ff8800 ICON_NAME=icon.png
```
Без `@Язык` строка меняется во всех языках.

**Остальные форматы** (`tools/resenc.py`; проверка `work/resenc_test.py`, сквозная — `work/resenc_e2e.py`):

| Что | Код формата | Как пишется | Проверка на стоке |
|---|---|---|---|
| звук MIDI / WAV / MP3 / AMR | 0 / 5 / 6 / 8 (`0xb` — заглушка `is null temply`) | файл как есть, код формата по сигнатуре | — |
| BMP | 1 | 16 бит, маски RGB565, заголовок 66 байт (DPI и прочие поля — из оригинала); `compression 0x1003` — строки снизу вверх тем же RLE, что ABMR (повтор с трёх, конец строки всегда повтор), `3` — без сжатия, строки до 4 байт | 2490 из 2495 байт в байт (у одного 240×16 в 5 сборках оригинал несёт 2 лишних нулевых байта в конце — артефакт их редактора) |

Не пишутся: анимация `VM` (одна во всей прошивке) и заглушка `user`.

Команды: `sresedit.py <mmi_res> --rings [папка]` — список звуков и выгрузка в файлы;
`ring:МОДУЛЬ:НОМЕР=файл.mp3`, `anim:МОДУЛЬ:НОМЕР=файл.gif`, картинки любого из форматов выше — из PNG (SGIF — из `.gif`,
обои — из любой картинки 240×320).

Ограничения: шрифты меняются через `tools/ttf2sfon.py`. На телефоне собранный файл ещё не проверялся;
ёмкость раздела MMIRes на флеше неизвестна — пока держим новый файл не больше исходного.

## Наблюдения

- Китайские шрифты `han` (7.2 МБ) и `hani` (4.7 МБ) — главная причина, почему ресурсы HK весят 18.6 МБ, а GB — 5.6 МБ (там только `latn`).
- В RU-моде `nogame4F2` поле `tres_size` указывает на 7 МБ при файле 18.5 МБ: только 34% байтов попадают в таблицы модулей.
  Из оставшегося 11.4 МБ — заливка `FF` до прежнего размера (шрифтов осталось 4 вместо 7), ~0.8 МБ — данные, на которые
  указывают записи, но лежащие вне таблиц: ResOver дописывает изменённые ресурсы и переставляет указатели, не перепаковывая файл.
- Все стоковые сборки (10.00, 11.00, 14.03, 15.00) теперь разбираются на 100% байтов, включая секции `logo`, `lang`, `cscs`.

Инструмент: `python3 -I tools/sres.py <mmi_res.bin>`.
