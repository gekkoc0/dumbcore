# fpdoom и spreadtrum_flash: eFuse, SD-загрузка, запуск своего кода (выжимка)

Разобрано по исходникам `work/src/fpdoom` и `work/src/spreadtrum_flash` (Илья Курдюков, public domain) +
`docs/links.md`. Всё это — **запуск кода в ОЗУ без записи во флеш**, ключевой безопасный полигон
для этапа «живой телефон». Статусы: «измерено» — строка/константа в исходнике, «оценка» — вывод.

## 1. eFuse UMS9117 (ответ на «какой бит Secure Boot»)

**Чтение** — `work/src/fpdoom/fpdoom/efuse.h` (ветка `#if UMS9117`):

- `EFUSE_BASE = 0x40240000` (совпадает с нашей `docs/internals/secureboot.md`), **64 слова по 32 бита** (`EFUSE_MAX=64`).
- Инициализация: включить такт `0x402e0000 |= 0x2000`, сброс `0x402e0008 |= 0x4000` → выждать → снять.
- Чтение слова `id` (0..63): `EFUSE_CR(0x48)=0xffff`, `EFUSE_CR(0x50)|=2`, `EFUSE_CR(0x40)=1 | dbl_bit<<2`,
  `EFUSE_CR(0x54)|=4`, взять `MEM4(0x40240000 + 0x1000 + id*4)`, снять `0x54`. `dbl_bit` — читать «двойной» (сырой,
  до коррекции ошибок) бит или декодированный.
- Инструменты: `fptest efuse` (`work/src/fpdoom/fptest/main.c:429 test_efuse`) печатает все 64 слова сырые и двойные;
  в `spd_dump` есть команда `read_efuse <файл|->` (`dump_efuse`, `spd_dump.c:1094`, команда FDL `0x6566`, 64 слова для
  UMS9117) — **только с самодельным FDL** (`t117_fdl` из spreadtrum_flash): с родными FDL выдаёт «custom FDL required».
  Это и лучший тест защиты: самодельный FDL не подписан, загрузится — значит, проверки нет.

**Какой бит = Secure Boot:** в fpdoom **не зашит** (есть только механизм чтения, не расшифровка слов). В нашей
прошивке бит проверяет BOOT1 `0x8010201e` (см. `docs/internals/secureboot.md`) — но какой именно бит, пока не выведено
(по-прежнему вопрос, `docs/internals/secureboot.md` §«Проверено на телефоне с ПО 16.00»). Практический способ: `fptest efuse`
на телефоне с известным состоянием и дифф слов. **Оценка.**

## 2. Признак Secure Boot: ответ ПЗУ `SPRD3`

В `spd_dump.c` (`work/src/spreadtrum_flash/spd_dump.c:1280`):

```c
if (memcmp(io->raw_buf + 4, "SPRD3", 6))
    secure_boot = 1;   // нет "SPRD3" → защищённая загрузка включена
```

На команду «check baud» ПЗУ отвечает версией; `SPRD3` — ответ аппаратов **без** включённой защищённой загрузки.
Наш телефон ответил `SPRD3` (`docs/backup.md`) → по признаку `spd_dump` **Secure Boot выключен**.
✔ измерено: ответ `SPRD3`. Но запуск *неподписанного* кода ещё не проверен — мы грузили родные
(подписанные) FDL. Прямое доказательство — загрузить самодельный `t117_fdl1.bin` или прочитать eFuse.

## 3. `t117_exec_dist 0x314d` (обход для Nokia)

В `spd_dump.c:1070` (`t117_exec_workaround`): для Nokia на UMS9117 вместо стандартного `BSL_CMD_EXEC_DATA`
шлётся команда `0x314d` с буфером из повторённого адреса запуска, **без ожидания ack**, и адрес сдвинут на
`+0x200` (заголовок DHTB). Команда `t117_exec_dist 0x314d` ставится **перед** `fdl` в строке `spd_dump`
(`work/src/fpdoom/README.md:170`). Без этого Nokia не переходит на загруженный код.

## 4. Загрузка с SD-карты (`sdboot_t117`)

`work/src/fpdoom/sdboot_t117/` — загрузчик, который **ПЗУ запускает с SD-карты** при зажатых клавишах:

- Ключи (позиции на плате, не кнопки): **(0,0)+(0,1)+(1,0)**. (0,0) — это загрузка с USB, то есть `*`;
  (0,1)/(1,0) — клавиши `bl_update` (`7` и `0` — их печатает `fphelper_t117` по нашему ядру). Итого `*`+`7`+`0`.
- Загрузчик пишется **в начало SD-карты** с сохранением MBR-разделов (`dd`, см. README).
- Если вставлена FAT32-карта — исполняется `fpbin_t117/fpmain.bin` (игра или меню `fpmenu`), аргументы — из
  `fpbin_t117/config.txt`.
- Бинарь обязан иметь заголовок **`DHTB`** (`MEM4(bin_addr) != 0x42544844` → ошибка), переход — на `bin_addr + 0x200`
  (`main.c:105`), то есть подпись **не проверяется** самим загрузчиком.
- ⚠️ `sdboot_t117/README.md:9`: «загрузчик должен быть подписан для телефонов с включённым Secure Boot». У нас
  Secure Boot выключен (`SPRD3`) → **загрузка с SD работает без подписи** — полигон для патчей кода (GIF-обои)
  без записи во флеш.

## 5. Как запускать fpdoom на Nokia 3210 4G

Из `work/src/fpdoom/ums9117/README.md` + `README.md`:

```sh
# нужны pinmap.bin/keymap.bin из своего ядра (уже извлечены fphelper_t117)
./spd_dump t117_exec_dist 0x314d \
    fdl t117_fdl1.bin 0x6200 \
    fdl fpdoom.bin 0x801M
cd workdir && ../libc_server -- --bright 50 --rotate 3 doom
```

- Для 3210: `--spi_mode 1 --bl_extra rgbw=0x14` (экран ST7789P3).
- `t117_fdl1.bin` — самодельный FDL1 из `spreadtrum_flash` (собран под UMS9117); родные FDL из `.pac` тоже
  приняты (`docs/backup.md`).
- `fpdoom.bin` — собрать с `T117=1` (Android NDK) или взять готовый из Releases автора (это чужой бинарный
  код — решайте сами).

## 6. Выводы для этапа «живой телефон»

1. **Secure Boot выключен** (`SPRD3`, измерено на телефоне с ПО 16.00; оценка до запуска неподписанного кода) → можно запускать неподписанный код:
   самодельный FDL, fpdoom, свои бинари.
2. **`fptest efuse`** (только чтение, в ОЗУ) — дамп всех 64 слов eFuse; подтвердит состояние и позволит
   диффом понять, какой бит = Secure Boot.
3. **SD-загрузка (`sdboot_t117`)** — безопасный полигон: загрузить изменённый код/USER с карты, флеш остаётся
   стоковым. Путь для экспериментов с патчем кода (GIF-обои) без риска.
4. **`t117_exec_dist 0x314d`** — обязателен для Nokia, чтобы ПЗУ перешло на загруженный код.
