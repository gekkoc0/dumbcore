# Структура интерфейса: что данные, а что код

Отвечает на вопрос «можно ли менять структуру/порядок интерфейса, а не только картинки».
Разобрано по USER_IMG 11.00.17.00 HK (Ghidra + декомпилятор). Статус «измерено» — видно в коде/данных.

## Вывод в двух строках

- **Главное меню (сетка/список на рабочем экране)** — данные: порядок в NV 680 (без подписи),
  смысл пунктов в статической таблице `s_mainmenu_item_data` (в подписанном USER_IMG).
- **Подменю (Параметры и любые вложенные меню)** — код: дерево строится динамически фреймворком
  `ctrlmenu` через вызовы в коде приложения. Таблицы данных нет.

## 1. Главное меню — данные

Декомпиляция читателя конфига `FUN_885abb06` (`mmi_mainmenu_data.c`):

- читает `config_item_count` и `main_menu_style`;
- идёт по позициям и для каждой ищет код пункта в статической таблице с **шагом 0x18 (24 байта)**
  и лимитом **0x32 (50 записей)** — это `s_mainmenu_item_data`, «50 записей × 24 байта» (совпадает
  с `docs/formats/nv-map.md`);
- таблица индексируется стилем меню: `база + main_menu_style * 0x4b0` (0x4b0 = 50 × 24 = блок на стиль).
- адрес таблицы (настоящий): указатель в USER `0x8833db80` (Ghidra `0x8833d980`) → `0x88b0f9e4`; поля картинок по стилям — docs/formats/nv-map.md.

Порядок кодов пунктов берётся из **NV 680** (`docs/formats/nv-map.md`). Итого главное меню = две части:

| Часть | Где | Подпись | Что даёт |
|---|---|---|---|
| порядок пунктов | NV 680 | нет | перестановка/скрытие/показ — свободно |
| смысл пункта (код → текст/иконка/фон/обработчик) | `s_mainmenu_item_data` | да (USER_IMG) | добавить новый пункт = новая строка таблицы + новый код |

## 2. Подменю — код (фреймворк `ctrlmenu`)

Подменю строит фреймворк `ctrlmenu` (файлы `ctrlmenu.c`, `ctrlmenu_export.c`, `ctrlmenu_options.c`,
`ctrlmenu_internal.c`, `ctrlmenu_popup.c`, `ctrlmenu_sec.c`, `ctrlmainmenu.c`). Из декомпиляции
`CTRLMENU_CreatDynamicEx` (`FUN_88a41a9a`) и строк по коду:

- каждое приложение **вызывает** `CTRLMENU_CreatDynamicEx(стиль, …)`, затем добавляет элементы через
  API (`AddItem`/`AppendItem`, напр. `CTRLCOMBOX_AddItemArray AppendItem failed`);
- дерево — рантаймовая структура в памяти: `group_ptr`, `parent_node_ptr->child_node_num`,
  `child_node_ptr`, `item_count` (`ctrlmenu_internal.c`/`ctrlmenu_options.c`);
- допустимые стили меню: **1, 5, 6, 7, 10 (0xb), 11 (0xe)** — сетка/список/попап.

Значит, порядок пунктов внутри подменю и иерархия «что куда вложено» = **порядок вызовов в коде
приложения**, а не таблица данных. Статической таблицы (как у главного меню) тут нет.

## 3. Что отсюда следует

| Что хотим | Возможно? | Чем |
|---|---|---|
| Переставить пункты главного меню | ✅ да | NV 680 (без подписи) |
| Показать/скрыть пункты главного меню | ✅ да | NV 680 |
| Переименовать/перекрасить пункты | ✅ да | ресурсы (`text`/`color`/`image`) |
| Переупорядочить/перестроить подменю | ⚠️ нет без патча | код приложения (подписан) |
| Добавить новый пункт/приложение | ⚠️ нет без патча | `s_mainmenu_item_data` + код (подписаны) |

- «Перерисовать интерфейс» — да, везде (ресурсы вне подписи).
- «Переставить главное меню» — да (NV 680).
- «Перестроить подменю» — только патчем USER_IMG, а это упирается в Secure Boot/eFuse
  (см. `docs/internals/secureboot.md`): если eFuse не прошит — патчим вызовы `ctrlmenu` и перестраиваем что угодно;
  если прошит — структура подменю закрыта.

Это объясняет, почему все моды с 4PDA трогают только главное меню (скрыть игры, добавить калькулятор/
диктофон/фонарик) и ни один не переставляет пункты внутри «Параметров»: там код, а не данные.

## 4. Фреймворк приложений (applet)

Приложения в MMI — это **апплеты** (applet), инфраструктура:

- `mmk_applet.c` / `cafapplet.h` / `cafapplet_gen.c` — узлы и экземпляры апплетов (`MMI_APPLET_NODE_T`);
- `MMI_RegAppletInfo` (`mmi_modu_main.c`, `0x885542b0`) — регистрирует таблицу `applet_info`
  (`static_module.applet_info_num` + `applet_info_pptr`);
- `mmi_applet_conflict.c` — конфликты: открытие одного приложения закрывает конфликтующее
  (`MMIAPIDCSRV_OpenMainWin close other app start!`, `CheckConflictApplet`).

Связь с меню: каждая строка `s_mainmenu_item_data` (50 записей) = один апплет (код меню → обработчик).
Поэтому **полный список приложений главного меню — это коды `0x01–0x24` из `docs/formats/nv-map.md`**, а
«вкл/выкл» = NV 680 (показать в сетке) + региональные флаги 621/641/660 (фичи MP3/Opera/Cloud).

Есть и **фоновые апплеты вне меню**: DAC (активация), NPS (опросы), счётчик трафика, call-control —
со своими id (`D_APPLET_ID`, `ORD_APPLET_ID`); в главное меню не входят.
